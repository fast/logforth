# Changelog

All significant changes to this project will be documented in this file.

## Unreleased

### Breaking changes

* Raise the minimum supported Rust version (MSRV) from 1.89.0 to 1.91.0.
* Upgrade `jiff` from 0.2 to 1.0 in `logforth-append-file`, `logforth-layout-json`, `logforth-layout-logfmt`, and `logforth-layout-text`.
* Upgrade `opentelemetry`, `opentelemetry-otlp`, and `opentelemetry_sdk` from 0.31.0 to 0.33.1 in `logforth-append-opentelemetry`.
* Remove the `anyhow` dependency from `logforth-core` and redesign `Error`: `Error::new` now accepts `impl Into<Cow<'static, str>>`, `Error::with_source` accepts `impl Into<Box<dyn std::error::Error + Send + Sync + 'static>>` instead of `impl Into<anyhow::Error>` and replaces any existing source instead of panicking, and `Error::{with_context, sources, from_io_error, from_fmt_error}` are removed. Walk `.source()` for causal chains and construct descriptive `Error::new(...).with_source(...)` values at call sites.
* Replace `Trap`, `trap::BestEffortTrap`, `AsyncBuilder::trap`, and `FileBuilder::trap` with `ErrorSink` and `error::{StderrErrorSink, BlackHoleErrorSink}` across `logforth-core`, `logforth`, `logforth-append-async`, and `logforth-append-file`. Configure runtime error handling via `LoggerBuilder::error_sink`, `DispatchBuilder::error_sink`, `AsyncBuilder::error_sink`, or `starter_log::LogStarter::error_sink` instead.
* Replace `&[Box<dyn Diagnostic>]` with `&dyn Diagnostic` across `Filter::filter`, `Layout::format`, `Append::append`, and `MakeBody::create` in `logforth-core`, `logforth`, and peripheral crates, and relax the `'static` supertrait bound on `Diagnostic` to the `Box<dyn Diagnostic>` registration boundary; traverse diagnostics via `diags.visit(&mut visitor)` instead of iterating a slice, and pass `&()` for an empty diagnostic context.
* Change `Layout::format` in `logforth-core` and built-in layouts to append formatted bytes into a caller-supplied `&mut Vec<u8>` and return `Result<(), Error>` instead of `Result<Vec<u8>, Error>`.
* Replace `Filter::{enabled, matches}` and `FilterCriteria` in `logforth-core` with `Filter::{filter_level(&self, level: Level) -> FilterResult, filter(&self, record: &Record, diags: &dyn Diagnostic) -> FilterResult}`, precomputing level bitmasks across `Level::ALL` at `Logger` build time and changing `Logger::enabled` to accept `Level` instead of `&FilterCriteria`.
* Remove `Record::target`, `RecordBuilder::{target, target_static}`, and `RecordOwned::target` from `logforth-core`, updating `PlainTextLayout`, `TextLayout`, `JsonLayout` (now serializing `"module_path"`), and `LogfmtLayout` to read `Record::module_path`, stopping `OpentelemetryLog` from calling `LogRecord::set_target` (preserving the configured `InstrumentationScope` name), and omitting the non-standard `TARGET` field in `Journald`.
* Change `Record::filename` from `Cow<'a, str>` to `Option<&'a str>` and `Record::key_values` from `&KeyValues<'a>` to `KeyValues<'a>` by value in `logforth-core`; unwrap or match `Record::filename` when a fallback empty string is needed.
* `RustLogFilterBuilder::{from_default_env, from_default_env_or, from_env, from_env_or, from_spec}` in `logforth-filter-rustlog` now return `Result<Self, Error>` and fail fast on malformed directives or non-UTF-8 environment variables instead of printing warnings to standard error, `RustLogFilterBuilder::{filter_level, filter_module}` are renamed to `{fallback, prefix}`, `RustLogFilterBuilder::try_from_spec` is removed, and `From<&str>` for `RustLogFilter` is replaced with `TryFrom<&str>`.
* Promote `Logger`, `LoggerBuilder`, `DispatchBuilder`, and `builder` to the `logforth` crate root (removing `logforth::core`), remove `starter_log::builder` and `LogStarterBuilder`, unify `LogStarterTestingBuilder` and `LogStarterStdStreamBuilder` into `starter_log::LogStarter`, and replace `apply` / `try_apply` with `starter_log::LogStarterExt::{install, try_install}` (implemented for `Logger`, `LoggerBuilder`, `LogStarter`, and `LogBridge`).
* Reserve the `logforth.` key prefix in key-value pairs for Logforth (`"logforth.target"` carries explicit `log` target overrides from `LogBridge` into `RustLogFilter`; see [DESIGN.md](DESIGN.md#appendix-key-value-naming-conventions)).
* `LogBridge::new` in `logforth-bridge-log` now accepts `Logger` by value instead of `impl Into<Arc<Logger>>`; pass `logger.clone()` when retaining another handle.
* Remove the `const APPEND: bool` generic parameter from `DispatchBuilder` in `logforth-core`; `DispatchBuilder::append` now returns `Self` in any order, and dispatches configured with no appenders are skipped when registered on `LoggerBuilder`.
* Remove `Copy` from `ThreadLocalDiagnostic` in `logforth-core`, `TaskLocalDiagnostic` in `logforth-diagnostic-task-local`, and `FastraceDiagnostic` in `logforth-diagnostic-fastrace`.
* `FutureExt::with_task_local_context` in `logforth-diagnostic-task-local` now accepts `IntoIterator<Item = (K, V)>` where `K: Into<KeyOwned>` and `V: Into<ValueOwned>` instead of `IntoIterator<Item = (String, String)>`, preserving typed values instead of converting them to strings, and nested task-local scopes now shadow outer entries for the same key; pass keys and values directly without `.into()` where type inference would otherwise be ambiguous.
* Require `Sync` on `kv::Value::{debug, display}` in `logforth-core` so `Value<'a>` implements `Send + Sync` (local formatters over non-`Sync` values can construct `kv::DebugValue::new` and `kv::DisplayValue::new` directly), replace `ValueOwned`'s `Box<Vec<...>>` and `Box<HashMap<...>>` storage with `Box<[u8]>`, `Box<[ValueOwned]>`, and insertion-ordered `Box<[(KeyOwned, ValueOwned)]>` slices (changing `ValueOwned::bytes` to accept `impl Into<Box<[u8]>>` and removing `ValueOwned::{from_vec, from_hash_map}` in favor of `ValueOwned::{list, map}`), and resolve duplicate keys in `KeyValues::get` and `MapValue::get` using last-entry-wins order.
* Change `StaticDiagnostic` and `ThreadLocalDiagnostic` in `logforth-core` to store `(KeyOwned, ValueOwned)` instead of `(String, String)`: `StaticDiagnostic::new` now accepts `IntoIterator<Item = (K, V)>`, `StaticDiagnostic::insert` accepts `K: Into<KeyOwned>` and `V: Into<ValueOwned>`, and `ThreadLocalDiagnostic::{insert, remove}` are replaced by `ThreadLocalDiagnostic::scope` returning a `!Send` `ThreadLocalDiagnosticGuard`.
* `File` in `logforth-append-file` now writes directly to target segment files instead of writing to an unnumbered active file and shifting reverse-numbered archives on rollover. Unrotated output remains `<filename>[.<suffix>]`, time-only rotation writes `<filename>.<period>[.<suffix>]`, and size rotation numbers segments in ascending order from `1` (oldest) as `<filename>[.<period>].<seq>[.<suffix>]`; `max_log_files` counts the active file toward the retention limit, and files created under the previous naming scheme are ignored or ordered by ascending sequence number until moved or removed.
* `FileBuilder::rollover_size` in `logforth-append-file` now takes `NonZeroU64` instead of `NonZeroUsize` and rotates before a write would exceed the size limit rather than after; update callers passing `NonZeroUsize` to pass `NonZeroU64`.
* `FileBuilder::build` in `logforth-append-file` now returns `Err` when `filename` or `filename_suffix` is empty, `.` or `..`, or contains path separators or NUL bytes.

### New features

* Add native structured logging macros (`log!`, `trace!`, `debug!`, `info!`, `warn!`, `error!`, and `fatal!`) in `logforth-core` and `logforth` supporting bracketed `"key" = value` fields on explicit `Logger` handles.
* Add `Error::message` and `RecordBuilder::time` in `logforth-core` to borrow an error's own message string and construct records with an explicit observed timestamp.
* Make `Logger` a pointer-sized `Clone` and `Default` handle over a shared pipeline and add `const fn Logger::noop()` in `logforth-core`, and implement `Clone` for `LogBridge` in `logforth-bridge-log`.
* Add `Level::ALL` in `logforth-core` and `ValueOwned::{from_serde, try_from_serde}` (behind the `serde` feature) to convert `serde::Serialize` values into structured `ValueOwned` trees without panicking.
* Add `LogBridge::max_level` in `logforth-bridge-log` and `starter_log::{LogStarterExt, LogStarter::try_build}` in `logforth`, updating `log::set_max_level` automatically from enabled logger levels on installation.
* Add `LoggerBuilder::error_sink`, `DispatchBuilder::error_sink`, and `starter_log::LogStarter::error_sink` to configure runtime error handling.
* Implement `Append`, `ErrorSink`, `Filter`, and `Layout` in `logforth-core`, and `MakeBody` in `logforth-append-opentelemetry`, for `Arc<T>` and `&'static T` where `T: ?Sized`, and implement `Diagnostic` for `&T`, `Arc<T>`, `()`, `Option<T>`, slices, arrays, and `Vec`.
* Add `FileBuilder::timezone` in `logforth-append-file` (and re-export `jiff`) to configure the timezone used for rotation boundaries and segment filenames, defaulting to the system timezone.
* Add `ThreadLocalDiagnostic::scope` and `ThreadLocalDiagnosticGuard` in `logforth-core` for `!Send` RAII scoped thread-local diagnostics that restore shadowed entries on drop.
* Add `kv::LogValue`, `Value::owned`, `DebugValue::new`, `DisplayValue::new`, `KeyView::to_static_str`, and `ValueView::to_bytes` in `logforth-core`, and implement `From` on `kv::{KeyOwned, ValueOwned}` across scalars, strings, byte slices, and `Option<T>`.

### Improvements

* Implement `Copy` for `kv::{Key, KeyView, Value, ValueView}`, `Clone` and `Debug` for `kv::KeyValuesIter`, and `kv::Visitor` for `FnMut(KeyView, ValueView) -> Result<(), Error>` closures in `logforth-core`.
* Make `LevelFilter::test`, `Record` field accessors, and `Record::to_builder` `const fn`, and return the closure result from `RecordOwned::with` in `logforth-core`; eliminate per-record `BTreeSet` lookups in `GoogleCloudLoggingLayout`, and format trace and span IDs on the stack without heap allocation in `FastraceDiagnostic`.
* Implement `Clone` for `RustLogFilter` in `logforth-filter-rustlog`, and precompute dual level masks so levels rejected or unconditionally passed across all directives short-circuit before prefix lookup.
* Map `kv::ValueView::Bytes` to `AnyValue::Bytes` in `logforth-append-opentelemetry`.

### Bug fixes

* `ValueView`'s `Display` implementation in `logforth-core` now formats list and map entries as values and string keys instead of exposing internal enum and wrapper names.
* `Logger::log` and `Logger::flush` in `logforth-core` no longer panic when writing internal error reports to standard error fails.
* `File` in `logforth-append-file` now opens segment files in append mode so external truncation does not leave NUL holes, avoids panicking on matching prefix and suffix edge cases or out-of-range timestamps, and avoids truncating rotation timestamps or file sizes on 32-bit targets.
* `TextLayout`, `LogfmtLayout`, `JsonLayout`, and `GoogleCloudLoggingLayout` now return `Err` instead of panicking on out-of-range record timestamps, `LogfmtLayout` quotes and escapes control characters in values and rejects control characters in keys, and `GoogleCloudLoggingLayout` gives explicit `Record` key-values precedence over colliding `Diagnostic` entries.
* `Async` in `logforth-append-async` now isolates panics in inner appenders during `append` and `flush` via `ErrorSink` instead of terminating the worker thread or panicking in `Drop`, and waits for full bounded queues to drain during `flush` under `overflow_drop_incoming` instead of dropping the flush barrier.
* `ThreadLocalDiagnostic` and `TaskLocalDiagnostic` now access thread-local storage via `LocalKey::try_with` so logging during thread-local teardown degrades to empty context instead of panicking.
